# 15 — Bilingüe español / inglés

> Requisito del cliente: **el sitio será en ambos idiomas y el visitante debe
> poder cambiar de idioma.**

Decidido el 2026-08-13, antes de crear las tablas de contenido. Llegar a esta
decisión después de la Fase 2 habría obligado a migrar el esquema entero y a
reescribir todas las vistas.

---

## 1. Alcance: qué se traduce y qué no

| Elemento | ¿Traducible? | Motivo |
|---|:--:|---|
| Textos de interfaz (botones, etiquetas, mensajes) | ✅ | Archivos `lang/` |
| Propiedades: título, slug, descripciones, SEO | ✅ | Es el contenido que posiciona |
| Noticias: título, slug, extracto, contenido, SEO | ✅ | Idem |
| Páginas (Invierte, Sobre nosotros, legales) | ✅ | Contenido editorial |
| Secciones del home (hero, CTAs) | ✅ | Contenido editorial |
| Tipos de propiedad ("Villa" / "Villa", "Solar" / "Lot") | ✅ | Aparecen en filtros y fichas |
| Amenidades ("Piscina" / "Pool") | ✅ | Idem |
| Cargo y biografía de agentes | ✅ | Contenido editorial |
| Mensajes de WhatsApp | ✅ | El cliente escribe en su idioma |
| SEO global por defecto | ✅ | |
| **Provincias, ciudades y sectores** | ❌ | *Santo Domingo* es *Santo Domingo*. Traducir topónimos dominicanos confunde y perjudica el SEO local |
| Nombre de la inmobiliaria, logo, teléfono, email, redes | ❌ | Son datos, no texto |
| Precios | ❌ | Ya resueltos por moneda (USD/DOP) |
| **Panel administrativo** | ❌ | El equipo es dominicano. El panel va en español; lo bilingüe es el *contenido* que se edita desde él |

## 2. Estrategia de URLs

**Español sin prefijo, inglés con prefijo `/en`, y segmentos traducidos.**

```
ESPAÑOL                        INGLÉS
/                              /en
/propiedades                   /en/properties
/propiedades/{slug-es}         /en/properties/{slug-en}
/invierte                      /en/invest
/sobre-nosotros                /en/about-us
/informate                     /en/insights
/informate/{slug-es}           /en/insights/{slug-en}
/contactanos                   /en/contact
/publica-tu-propiedad          /en/list-your-property
/comparar                      /en/compare
```

**Por qué así y no `/es/...` + `/en/...`:**

1. El prompt maestro (§12 y §17) fija esas URLs españolas como requisito. Cambiarlas a `/es/propiedades` incumpliría el contrato.
2. El público principal es dominicano; el español es el idioma por defecto y no debe pagar un redirect ni un prefijo.
3. Es un patrón estándar y bien soportado por Google, siempre que el `hreflang` esté correcto.

**Coste asumido:** si algún día se añade un tercer idioma, la asimetría queda algo torcida. Es reversible con redirecciones 301, pero es más barato decidirlo ahora — está anotado como decisión revisable.

**Segmentos traducidos, no `/en/propiedades`:** un inglés que busca *"properties for sale Punta Cana"* encuentra mejor una URL con `properties` dentro. Es la razón de ser del bilingüe.

## 3. Almacenamiento de las traducciones

Se usan **dos mecanismos según la naturaleza del dato**. No es inconsistencia: responden a necesidades distintas.

### 3.1 Tablas de traducción — para lo que se busca y posiciona

`properties`, `news_posts`, `pages`, `content_sections`.

```
property_translations
- id
- property_id      FK CASCADE
- locale           char(2)          -- 'es' | 'en'
- title            varchar(200)
- slug             varchar(220)
- short_description varchar(500) NULL
- description      text NULL
- meta_title       varchar(200) NULL
- meta_description varchar(300) NULL
- timestamps

UNIQUE (property_id, locale)
UNIQUE (locale, slug)               -- el slug es unico DENTRO de cada idioma
FULLTEXT (title, short_description, description)
INDEX (locale)
```

**Por qué tabla y no columna JSON:** el slug tiene que ser único por idioma (no se puede con JSON), y la búsqueda necesita `FULLTEXT` por idioma (tampoco se puede indexar dentro de un JSON). Estas dos entidades son justo las que se buscan y se posicionan.

Análogas: `news_post_translations`, `page_translations`, `content_section_translations`.

### 3.2 Columnas JSON — para catálogos y textos cortos

`property_types`, `amenities`, `agents`, `settings`.

```
property_types.name  →  {"es": "Villa",   "en": "Villa"}
amenities.name       →  {"es": "Piscina", "en": "Pool"}
agents.position      →  {"es": "Asesor Senior", "en": "Senior Broker"}
```

No llevan slug propio ni se buscan por texto libre, así que la simplicidad del JSON gana: sin joins extra en cada listado.

En `settings` se añade `is_translatable`; si está activo, `value` guarda el JSON por idioma. Claves traducibles: `site_tagline`, `footer_text`, `seo_default_title`, `seo_default_description`, `contact_schedule`, y los tres mensajes de WhatsApp. **No** traducibles: teléfono, emails, redes, logo, favicon.

### 3.3 Regla de respaldo

Si falta la traducción inglesa, **se muestra la española** en vez de un hueco.
La ficha aparece igual, y el panel marca en el listado qué contenido está sin traducir. Nunca una página en blanco por un campo vacío.

Excepción: si una propiedad **no** tiene traducción inglesa, su URL `/en/...`
lleva `hreflang` pero se marca como contenido de respaldo; nunca se genera un
slug inglés inventado.

## 4. Textos de interfaz

```
lang/
├── es/
│   ├── common.php      navegación, botones, pie
│   ├── property.php    estados, operaciones, características
│   ├── forms.php       etiquetas, ayudas, validación
│   └── seo.php         plantillas de meta
└── en/
    └── (los mismos)
```

Regla: **ningún texto visible queda escrito dentro de un Blade.** Todo pasa por
`__('common.search')`. Un texto quemado es un texto que jamás se traduce.

## 5. Selector de idioma

En el header, junto a los botones de acción; en el menú móvil, como fila propia.

Comportamiento:

- Cambia a **la misma página** en el otro idioma, no a la portada. Estar viendo una villa en Cap Cana y acabar en la home al pulsar "EN" es la forma más rápida de perder al visitante.
- En fichas de propiedad y noticias, resuelve el **slug traducido** de esa misma entidad.
- Si la traducción no existe, lleva al listado equivalente y avisa.
- Guarda la preferencia en cookie (1 año) para visitas siguientes.
- Se marca con `rel="alternate"` y `hreflang`.

**Sin redirección automática por IP o por `Accept-Language`.** Google la penaliza al rastrear, y un dominicano usando un navegador en inglés acabaría en la versión que no quiere. El idioma lo elige la persona, no una heurística.

## 6. SEO bilingüe

En cada página:

```html
<link rel="alternate" hreflang="es"       href="https://erarealtyrd.com/propiedades/villa-cap-cana">
<link rel="alternate" hreflang="en"       href="https://erarealtyrd.com/en/properties/cap-cana-villa">
<link rel="alternate" hreflang="x-default" href="https://erarealtyrd.com/propiedades/villa-cap-cana">
```

- `x-default` apunta al español.
- `<html lang="es|en">` y `og:locale` `es_DO` / `en_US`, con `og:locale:alternate`.
- **Sitemap con ambos idiomas**, cada URL declarando sus alternativas.
- El `canonical` de cada página apunta a sí misma, nunca al otro idioma.

Actualiza lo escrito en [07_SEO.md](07_SEO.md).

## 7. Impacto en el panel

Los formularios de propiedades, noticias, páginas y secciones ganan **pestañas de idioma** (ES | EN) sobre los campos traducibles. El resto de campos (precio, habitaciones, ubicación, imágenes) es común a ambos idiomas y no se duplica.

- Indicador de "sin traducir" en los listados.
- El slug se genera por idioma desde su propio título.
- Vista previa por idioma.
- La imagen y los datos numéricos **no** se duplican: una propiedad es una, con dos textos.

## 8. Impacto en las fases

| Fase | Cambio |
|---|---|
| 0 | Infraestructura de locale: config, middleware, rutas, `lang/`, selector |
| 1 | `settings.is_translatable` + campos ES/EN en configuración |
| 2 | `property_translations`; JSON en tipos y amenidades; pestañas de idioma |
| 4 | Todas las vistas con `__()`; selector en header y menú móvil |
| 6 | `news_post_translations` + editor por idioma |
| 8 | `hreflang`, sitemap bilingüe, `og:locale:alternate` |
| 10 | Pruebas en ambos idiomas |

**Coste estimado:** entre un 20 % y un 25 % sobre el plan monolingüe. La mayor parte se concentra en las fases 2, 4 y 6.
